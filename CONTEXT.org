* Domain Glossary & Ubiquitous Language

** 1. Structural & Isolation Roles
- *AST (Abstract Syntax Tree)* :: A pure, in-memory tree representation of parsed markup or code (e.g., Org-mode syntax nodes). It is completely decoupled from any UI framework, DOM node, or platform API.
- *Host Application* :: The third-party web application (e.g., Gemini, DuckDuckGo AI / ~duck.ai~, ChatGPT, Claude) running in the browser tab that the extension inspects and augments.
- *Host Node* :: A native DOM element created and managed by the Host Application's internal framework (e.g., a native ~<code-block>~ or message container).
- *Injection Container* :: A lightweight wrapper element created by the extension and inserted as a sibling or wrapper to a Host Node to serve as the mounting anchor for custom UI.
- *In-Situ Sibling Container* :: A specialized injection container mounted as an adjacent sibling to a native host code block element, attaching an open Shadow Root and rendering an improved header (with equivalent and custom action buttons) and the parsed ~DocumentView~ (via ~InSituCodeBlockContainer~) while hiding the native host code block via ~display: none~.
- *InSituCodeBlockContainer* :: The universal Preact component mounted inside the In-Situ Sibling Container orchestrating block folding, view mode transitions ("rendered" vs "raw"), and host copy parity.
- *Data-Island* :: The superseded native host code DOM element (e.g., ~:scope code-block code~ in Gemini; ~div[data-streamdown="code-block-body"] pre > code~ in Duck.ai) retained in the DOM tree in a hidden state (~display: none~), serving as the authentic, unmutated payload source for scrapers, clipboard actions, and host re-evaluations.
- *Shadow Root Boundary* :: An encapsulated DOM subtree (~mountContainer.attachShadow({ mode: 'open' })~) isolating extension styles (~adoptedStyleSheets~) and Preact component trees from host CSS resets and global styles.
- *Non-Destructive Host Bypass* :: The immediate non-intervention decision made by a host injector when a code block's canonical format lacks an alternate rendered view in the ~RendererRegistry~ (~rendererRegistry.has(formatId) === false~), leaving native host elements, syntax highlighting, and controls completely untouched without injecting sibling containers or hiding host DOM nodes. Matching a format via ~MatcherRegistry~ does not imply having a rendered view.

** 2. Architectural Layers & Components
- *Pure Domain Contracts (~src/contracts/core/~, ~src/contracts/chats/~, ~src/contracts/features/*~)* :: Headless, deterministic TypeScript interfaces containing domain models, lifecycle states, and capability contracts (organized by capability submodules). Strictly decoupled from DOM, Preact, and WebExtension APIs.
- *Feature Registries (~src/registries/~)* :: Pure TypeScript in-memory registries (~chatRegistry~, ~rendererRegistry~, ~parserRegistry~, ~serializerRegistry~, ~matcherRegistry~) managing independent capability lookup, factory dispatch, and asynchronous loading (~load: () => Promise<T>~) across the feature pillars. Having a matcher registered does not imply having a parser or renderer.
- *Canonical Format ID Pipeline* :: The single-pass ingestion workflow where ~matcherRegistry.findMatching()~ resolves raw hint and lines into an immutable canonical ~formatId~. Downstream containers, parsers, and renderers consume this identifier directly with zero rematching.
- *Five-Pillar Feature Hierarchy (~src/features/~)* :: The decoupled extension capability model organizing all platform integrations and format capabilities into five single-responsibility pillars:
  1. *Chat Host Adapters (~features/chats/~)*: Encapsulates provider-specific DOM scraping, mutation listening, stream settlement detection (~SettlementObserver~), Shadow DOM injection, and theme authority (~HostThemeAuthority~) behind the unified ~SiteAdapter~ contract. Loaded lazily by URL hostname predicate in ~ChatRegistry~.
  2. *Format Matchers (~features/matchers/~)*: Pure, synchronous, eager (0ms) heuristic matchers bundled into the bootloader to resolve language hints and leading lines into canonical ~formatId~s (implementing ~FormatMatcher~).
  3. *Syntax Parsers (~features/parsers/~ / ~features/ast/~)*: Lazy, headless syntax parsers loaded on-demand during stream settlement or export to convert raw text into Abstract Syntax Trees (implementing ~Parser~).
  4. *Document Renderers (~features/renderers/~)*: Lazy Preact presentation components mounted inside open Shadow Roots to render interactive views of parsed ASTs (implementing ~Renderer~, ~DocumentViewProps~).
  5. *Conversation Serializers (~features/serializers/~)*: Pure domain encoders converting conversational turns and branch paths into structured document syntax (implementing ~ConversationSerializer~).
- *In-Situ Presentation Layer (~src/views/~)* :: Universal Preact components (~InSituCodeBlockContainer~, ~StructuredMessageContainer~, ~FloatingHUD~) orchestrating view modes ("rendered" vs "raw"), block folding, copy parity, and export actions inside isolated Shadow Roots.
- *Platform & Storage Adapters (~src/core/storage/~, ~src/core/rpc/~)* :: Abstractions wrapping browser-specific runtime APIs (~browser.storage~, ~browser.runtime.sendMessage~) behind typed Promise-based contracts.
- *Dynamic Import Bootloader (~content.js~)* :: A lightweight, zero-dependency classic content script injected by Manifest V3 that dynamically imports the extension's modular entrypoint (~import(browser.runtime.getURL("app.js"))~), enabling isolated ES module execution, relative split chunk resolution, and full CSP compliance.
- *Native Deno 2 Bundler (~build.ts~)* :: The build pipeline utilizing Deno 2's native ~deno bundle~ command with ~--platform browser~ and ~--code-splitting~ to emit optimized, modular JavaScript chunks without external npm bundler dependencies, coupled with in-process Tailwind CSS v4 compilation and explicit manifest chunk registration.
- *Browser Action Toolbar Toggle* :: The WebExtension action control providing one-click activation/deactivation, executing a full, non-destructive teardown (~adapter.destroy()~, ~injector.destroyAll()~) on deactivation and seamless re-mounting on activation.

** 3. Lifecycle & State Machine Concepts
- *Micro-Debouncing (Observer Batching)* :: An execution delay (200ms minimum) applied to ~MutationObserver~ events to coalesce high-frequency DOM changes before processing.
- *Macro-Settling (Stream Finalization)* :: The state-machine heuristic (e.g., >300ms mutation silence, host completion indicators, or stop-button disappearance) used to determine that the LLM has finished streaming a response.
- *In-Flight Phase (Streaming)* :: The transient state during token arrival where heavy AST parsing and interactive Preact mounting are suspended in favor of lightweight native/text updates.
- *Settled Phase (Finalized)* :: The stable state reached after token generation completes, triggering full AST parsing, syntax highlighting, and interactive Preact view mounting.
- *Mount Guard* :: Explicit HTML dataset attributes (~data-ext-processed~, ~data-ext-mounted~) set on DOM elements to make scrapers and injectors strictly idempotent across multiple observer passes.
- *Decoupled LRU Cache* :: An in-memory cache keyed by content hash (fast FNV-1a fingerprint of code prefix, length, and canonical formatId) that stores parsed ASTs and view state independent of physical host DOM node lifecycle, surviving virtual-scroller recycling.
- *Conversation Turn* :: The atomic conversational unit composed of a paired user query (raw string) and a model response (array of segmented child elements: ~ResponseSegment~ discriminated union covering prose, code blocks, tables, and math display), including completion status flags (~isCompleted: boolean~) and deterministic lineage tracking.
- *Conversation Tree Store* :: A persistent append-only tree repository in ~browser.storage.local~ preserving all conversation turns, edits, and regenerated branches across sessions, enforcing an internal automatic LRU eviction policy (<8MB threshold) to operate within the 10MB quota without extra permissions.
- *Message Destruction Signal* :: Observer event triggered on DOM node removal to safely unmount Preact roots without purging persistent AST caches.

** 4. Org-Mode & Content Domain Concepts
- *Org AST (Abstract Syntax Tree)* :: The strongly-typed data representation of an Org-mode document produced by the universal document parser (~src/languages/org/ast/~) and inline lexers.
- *Heading Node & Subtree* :: A hierarchical Org section (~*~ through ~******~) containing title tokens, status chips (~TODO~, ~DONE~), priority badges (~[#A]~), tag sets (~:TAG:~), and nested child content folded recursively.
- *Property Drawer* :: Metadata blocks enclosed in ~:PROPERTIES: ... :END:~ containing key-value pairs, collapsible via interactive toggles.
- *Cookie Progress* :: Dynamic checkbox fraction indicators (e.g. ~[2/5]~ or ~[40%]~) that recalculate in real-time as child checkboxes are clicked.
- *OrgMetadataCommentNode* :: First-class AST node representing ~#+KEY: VALUE~ lines, storing the case-insensitive normalized keyword as ~metaType~, optional bracketed arguments, and value payload.
- *Affiliated Keywords* :: Metadata comments (such as ~#+NAME:~, ~#+CAPTION:~, ~#+ATTR_...~) immediately preceding a structural block element (code block, table, list) without an intervening blank line, attached directly to that element as ~affiliatedMetadata~ rather than emitted as standalone siblings.
- *Lenient Pipe Table Normalization* :: Table parsing heuristic that auto-closes missing trailing pipes, trims whitespace, and pads columns across rows to match the table's maximum column count.
- *OrgMacroNode* :: Pure, un-mutated AST node representation for Org macro invocations (~{{{name(args)}}}~), preserving raw syntax without eager expansion during the parsing pass.
- *AstCache* :: In-memory LRU cache storing parsed AST trees keyed by 32-bit FNV-1a content hash and canonical formatId (~"org"~), decoupling AST lifetime from host DOM virtual scroller lifecycles.
- *Turn Metadata Drawer* :: Machine-readable property drawer (~:PROPERTIES: ... :END:~) affixed to conversation turn headlines containing role, indices, and timestamps.
- *StructuredMessageContainer* :: Universal Preact container component providing a unified interface for message boxes in the DOM, orchestrating folding, collapsed summary badges, portal toolbars, and active view projection.
- *Headline-Scoped Subtree Copy* :: Pure AST serialization (~serializeOrgSubtree~) extracting the complete textual representation of an Org headline, its planning line, property drawers, body content, and nested sub-headlines into the clipboard with green confirmation feedback.
- *Display Math Block* :: Standalone or embedded mathematical equation delimited by ~$$...$$~, ~\[...\]~, or ~\begin{equation}...\end{equation}~ rendered as an isolated, horizontally scrollable centered block container with vertical spacing, distinct from inline LaTeX fragments. Protected by two-phase tokenization: delimited and shielded first before entity expansion.
- *Headline Visibility Cycling* :: Canonical 3-state outline visibility cycling on Org headlines: ~folded~ (header card only, fold indicator ~▶~, title ellipsis ~...~, body and children hidden), ~children~ (direct child headlines revealed in ~folded~ state, direct paragraphs hidden), and ~subtree~ (entire hierarchy fully expanded).
- *Descendant State Pruning* :: The policy of clearing all cached fold state entries for nested descendant headline paths (~<id>.c-...~) whenever a parent headline collapses to ~folded~, ensuring subsequent expansions start from a clean baseline.
- *Code Block Heading Parity* :: The conceptual unification of the outer code block container header with document outline headlines, treating the block header as an encompassing top-level heading ($H_0$) whose primary folding behavior mirrors headline outline cycling rather than disjoint mode toggling.

** 5. UI Controls & Styling
- *Floating HUD (Heads-Up Display)* :: An ephemeral floating control panel elevated above the bottom-right corner providing width presets, view toggles, font size controls, and export triggers.
- *Three-Layer Style Mapping* :: Decoupled styling architecture separating pure domain computation (~computeLayoutStyles~), DOM I/O adapters (~applyLayoutDeclarations~), and reactive Preact hooks (~useLayoutSync~).
- *Version Overlay* :: Top-center Preact-rendered overlay badge mounted exclusively during development (~__DEV__ === true~) displaying dynamic dev build identifiers.
- *View Mode* :: The active presentation state (~"rendered"~ vs ~"raw"~) of a supported code block within the In-Situ Sibling Container.
- *Block Folding* :: The collapsible presentation state hiding the code block body while preserving the header toolbar, language badge, and copy actions in an operable state.
- *Tailwind Inlined Stylesheet* :: Pre-compiled Tailwind CSS v4 utility suite inlined directly into the extension bundle as a generated module string constant, completely bypassing network requests (~browser.runtime.getURL~ / ~fetch~) and enabling 100% offline, CSP-compliant styling.
- *AdoptedStyleSheet Singleton* :: A single ~CSSStyleSheet~ constructed and cached once in memory (~new CSSStyleSheet()~, ~sheet.replaceSync(TAILWIND_CSS)~), adopted across all injected open Shadow Roots (~shadowRoot.adoptedStyleSheets = [sharedSheet]~), guaranteeing 0ms hydration and zero duplicate memory allocations across virtual scroller lifecycles.
- *Shadow DOM Host Theme Variant* :: Tailwind selector mapping (~@variant dark (:where(:host([data-theme="dark"]) &, [data-theme="dark"] &));~) coupled with inner container ~data-theme~ attribute projection, ensuring ~dark:...~ utility classes respond dynamically to host dark mode across shadow boundaries.
- *Host-Specific Theme Contract* :: The structural interface allowing site adapters to define custom theme tokens, overrides, or color mappings without polluting universal Preact presentation components.
- *Right-Anchored Leftward Expansion* :: The positioning constraint for the Floating HUD anchoring the container to its right edge, expanding horizontally outwards to the left and collapsing to the right, enabling placement against the right screen edge without off-screen clipping.
- *Conversation Tree Export Flyout* :: The interactive HUD flyout visualizing the conversation branch tree with node checkboxes, enabling users to select and export one or more root-to-leaf paths as unified multi-turn documents.

** 6. Observability & Telemetry
- *Runlevel* :: The operational execution mode of the extension (~dev~, ~test~, ~prod~) establishing baseline operational presets, dev tooling availability, and default log verbosity thresholds.
- *Log Level* :: The severity threshold (~DEBUG~, ~INFO~, ~WARN~, ~ERROR~, ~SILENT~) determining whether a telemetry entry is emitted to native console sinks and in-memory buffers.
- *CoreLogger* :: The centralized logging subsystem (built on LogTape under ~src/core/logging/~) providing structured, namespaced telemetry (e.g. ~ext:gemini~, ~ext:duckai~, ~ext:storage~) with dynamic runlevel filtering and in-memory ring buffer capture.
- *Origin-Filtered Error* :: A browser error or unhandled Promise rejection verified via script URL (~browser.runtime.getURL~) or stack trace to have originated strictly from the extension's execution contexts rather than host application scripts.
- *Diagnostic Ring Buffer* :: A fixed-capacity in-memory circular buffer retaining the latest log entries in JavaScript memory for active session inspection and automated test assertions without persistence overhead.

* System Architecture & Extension Ruleset

** 1. Architectural Layers & Boundary Invariants
The codebase enforces a strict directional dependency graph:

#+BEGIN_EXAMPLE
Domain (Pure) & Registries  <-  Store / Platform Adapters  <-  Controllers / Scrapers (DOM)  <-  Views / UI (Preact / Shadow DOM)
#+END_EXAMPLE

*** 1.1 Pure Domain & Headless Registries (~src/contracts/~, ~src/registries/~, ~src/features/matchers/~, ~*/ast/~, ~*/model/~)
- 100% pure TypeScript/ECMAScript with zero external runtime dependencies.
- Headless in-memory registries (~src/registries/~) manage service resolution and capability lookups using pure TS data structures.
- STRICTLY FORBIDDEN: Preact, React, JSX/TSX, CSS/style imports, Browser DOM APIs (~window~, ~document~, ~HTMLElement~, ~MutationObserver~), and WebExtension APIs (~browser.*~).
- Invariant: Must execute deterministically across headless targets (MV3 ~background.ts~ worker, Web Workers, Node/Deno unit tests).

*** 1.2 Platform & Storage Adapters (~src/core/storage/~, ~src/core/rpc/~)
- *Firefox-First & Unified Browser API Invariant*: The extension is built primarily for Firefox WebExtensions and targets the unified ~browser.*~ namespace. Chrome compatibility is secondary and by coincidence. Code must never invoke or assume ~chrome.*~ directly; all platform operations must prioritize standard ~browser.*~ APIs.
- Encapsulates WebExtension APIs exclusively via the standard ~browser.*~ namespace.
- Direct invocation of ~browser.storage.local~ across arbitrary UI or scraper modules is forbidden; all persistent operations route through typed storage abstractions.
- RPC message contracts use native Promise resolution over ~browser.runtime.sendMessage~ and ~browser.runtime.onMessage~.

*** 1.3 DOM Scraping & Host Controllers (~src/features/chats/*/scraper.ts~, ~domObserver.ts~, ~injector.tsx~)
- Manages host DOM inspection, mutation listening, and lifecycle orchestration.
- May consume Browser DOM APIs, platform storage, pure domain contracts, and registries.
- STRICTLY FORBIDDEN: Direct UI framework imports (Preact/React/JSX) and direct HTML rendering.
- Telemetry & Fallbacks: Selectors must prioritize semantic custom elements (e.g., ~model-response~, ~code-block~) with secondary structural fallbacks (e.g., ~pre > code~). Scrapers run non-throwing diagnostic health checks on load to log DOM schema drift.

*** 1.4 Presentation & View Layer (~*/views/~, ~*/ui/~, ~src/views/~)
- Houses Preact components, hooks, and stylesheets.
- Mounts inside isolated Shadow Roots attached to host injection containers.
- May import domain contracts, registries, and controllers; domain layers must NEVER import presentation layers.

*** 1.5 Module Packaging & Deep Import Invariant
- Barrel files (~index.ts~) must NEVER co-export headless domain logic alongside UI components.
- *Submodule Contract Barrels*: All contracts under ~src/contracts/~ must be imported from their explicit submodule barrel (e.g., ~@/contracts/core~, ~@/contracts/chats~, ~@/contracts/features/parsers~). Monolithic root barrels (~src/contracts/index.ts~) are strictly prohibited to prevent circular dependencies and accidental transitive bundling.
- Headless execution targets must import explicit deep paths (e.g., ~@/languages/org/ast~) to guarantee zero DOM/CSS evaluation during tree-shaking.

*** 1.6 Prohibition of Backwards Compatibility Facades
- Never retain deprecated re-export bridges, wrapper shims, or backwards-compatibility facades to cover up incomplete refactoring.
- When relocating or renaming modules, contracts, or directory paths, execute an exhaustive and complete migration across 100% of callers, tests, and documentation, and immediately delete the superseded files.

** 2. Host DOM Integration & Mutation Lifecycle

*** 2.1 Non-Destructive Host Mutation
- Never call ~.remove()~, clear ~.innerHTML~, or alter the internal children of host SPA nodes.
- Hide superseded host nodes strictly via styling properties (~display: none~ or ~hidden~ attribute) to preserve host virtual DOM state, event listeners, and native actions (copy, retry).

*** 2.2 Idempotent Mount Guards
- Nodes targeted for processing must be tagged before execution:
  - ~element.dataset.extProcessed = "true"~ (scraped / parsed)
  - ~element.dataset.extMounted = "true"~ (UI active)
- All injection and scrape routines must verify dataset tags before acting to guarantee idempotency across duplicate observer dispatches.

*** 2.3 MutationObserver Batching vs. Stream Settling
- Mutation Batching: Wrap observer handlers in debouncing (200ms minimum) to batch continuous host streaming events. Filter out mutations originating from extension-tagged subtrees.
- Stream Settlement State Machine:
  - *Phase A (In-Flight / Streaming)*: Maintain native view or lightweight plaintext streaming buffer while active stream markers (mutation frequency, typing cursors, stop buttons) exist.
  - *Phase B (Finalized / Settled)*: Trigger complete AST generation and Preact component mounting only after stream termination criteria are met (host completion indicators, stop-button disappearance, or >300ms mutation silence).

*** 2.4 View Lifecycle & Cleanup Registry
- Every mounted Preact root must be registered in a centralized ~Map<string, { root: HTMLElement, destroy: () => void }>~.
- Adapters must provide an idempotent ~destroy()~ method that runs ~render(null, shadowRoot)~, removes injected sibling containers, and restores host element visibility.

*** 2.5 The Abstract Turn & Multi-Platform Discovery
- *Abstract Turn Contract*: The Conversation Turn is a foundational domain concept representing the paired user prompt and assistant response, its completion status (~isCompleted: boolean~), and its segmented output payload (~ResponseSegment~). The turn is an abstract model that all supported chat platforms must satisfy, but which each host realizes and bounds differently in the physical DOM:
  1. *Gemini Composite Container*: Encapsulates both query and response within a single outer container ~div.conversation-container[id]~, containing child elements ~user-query~ (~span.user-query-container~) and ~model-response > response-container~. Completion is signaled by ~.response-container-footer message-actions[footer]~.
  2. *Duck.ai Flat Message Stream*: Employs a decoupled message stream where user queries and assistant responses are rendered as independent sibling items (~article[data-testid="message"]~ / message stream items). The adapter dynamically associates the user message article with the subsequent assistant message article into a logical turn. Completion is signaled by ~div[data-message-actions="true"]~ and the disappearance of ~button[aria-label="Stop generating"]~.
- *Non-Replacement Invariant*: Conversational turn containers are strictly used for turn boundary discovery, lineage tracking, and persistent backup—never for full UI replacement. In-situ augmentation targets individual code blocks incrementally.

*** 2.6 SPA Route Changes & In-Session Chat Switch Resilience
- Single Page Applications (Gemini, Duck.ai) navigate between conversations client-side without full page reloads.
- Adapters must intercept History API state transitions by hooking ~window.popstate~ and wrapping ~history.pushState~ / ~history.replaceState~.
- Route changes compare URL pathnames and root container identities to differentiate in-chat prompt submissions from true conversation switches.
- On conversation switch, the adapter synchronously invokes ~teardown()~ on the active session (unmounting mounted Preact roots via ~injector.destroyAll()~, disconnecting active mutation observers, and resetting in-flight turn contexts), then re-binds observers to the newly mounted stream container.

** 3. View Encapsulation & Memory Management

*** 3.1 Shadow DOM Boundary
- Mount interactive views inside open Shadow Roots: ~mountContainer.attachShadow({ mode: 'open' })~.
- Inject component stylesheets via ~shadowRoot.adoptedStyleSheets = [sheet]~ using an in-memory ~CSSStyleSheet~ singleton populated from the inlined Tailwind bundle (~sheet.replaceSync(TAILWIND_CSS)~), ensuring zero network fetches and 0ms paint.
- For non-shadow injection wrappers, prefix all selectors with ~.ext-*~ and explicitly reset host typography inheritance.

*** 3.2 Decoupled In-Memory Cache (Virtual Scroller Defense)
- Do not store state on host DOM nodes subject to virtual unmounting/recycling.
- Cache parsed ASTs and view state in a decoupled in-memory LRU cache keyed by a content hash. Do not rely on host-created UUIDs.
- Scrolling a recycled message into the viewport reads from the LRU cache and hydrates immediately without re-parsing raw text.

* Host Platform Specifics & Standardized DOM Hierarchies

** Standardized Host Hierarchy Policy
Every supported chat platform (current and future) MUST have a standardized ASCII DOM hierarchy diagram and structural description documenting its container nesting, semantic selectors, code extraction anchors, and action footers.
- *Missing Hierarchy / Drift Policy*: If an ASCII DOM hierarchy is not immediately available when onboarding a new chat host or when auditing an existing host whose DOM schema has evolved, an explicit note of this deficiency must be recorded in ~CONTEXT.org~ and a tracking ticket MUST be created under ~.scratch/<feature>-adapter/issues/~ (during active feature development) or ~.scratch/technical-debt/issues/~ (during general audits) to document and verify it.

** 1. Gemini Platform Adapter

*** 1.1 Plaintext Extraction vs. Highlighted Syntax
- Format identification is delegated to the pure ~MatcherRegistry~ (~matcherRegistry.findMatching(rawHint, rawLines)~).
- The Gemini scraper extracts the raw header hint string (prioritizing specific container classes such as ~.code-block-decoration~ and ~.header-content~ rather than walking arbitrary text nodes) and the leading lines of code block content.
- Registered eager format matchers (~OrgMatcher~, ~MarkdownMatcher~, ~JsonMatcher~) evaluate hints and content heuristics in priority order. For generic hints (~"Code snippet"~, ~"Plain text"~), content patterns (e.g. Org headline regex ~^\*+\s~ or ~^#\+TITLE:~) resolve the canonical ~formatId~.
- If ~rendererRegistry.has(formatId)~ returns false (e.g., for JSON or unsupported formats), Non-Destructive Host Bypass immediately leaves native host elements, buttons, and syntax highlighting completely untouched.
- If true, ~formatId~ is passed downstream to ~InSituCodeBlockContainer~ without any downstream rematching.

*** 1.2 Streaming DOM & Debounced Injection
- Target ~infinite-scroller~ / ~.conversation-container~ with ~MutationObserver~ (~childList: true, subtree: true~).
- Apply debouncing (200ms minimum) during active streaming.
- Transition from streaming buffer to interactive Preact mount only upon settlement (>300ms mutation silence or presence of response footer actions).
- Completion vs. Interruption Detection: The presence of ~.response-container-footer message-actions[footer]~ indicates normal completion (~isCompleted = true~). If mutations cease for $>2$ seconds without footer actions appearing, the turn is recorded in storage with ~isCompleted = false~ (cancelled or interrupted).
- Check ~dataset.extProcessed~ and ~dataset.extMounted~ to guarantee idempotency.

*** 1.3 Sibling Mount Anchor & Data-Island Pattern
- The ~Injection Container~ mounts as a sibling to ~<code-block>~ inside ~<response-element>~.
- The superseded ~:scope code-block code~ element serves as a read-only *Data-Island* containing the authentic LLM output text.
- The native ~<code-block>~ is hidden via ~display: none~, preserving host nodes, native text, and accessibility trees without destructive DOM mutation.
- The sibling Preact root mounts inside an open Shadow Root upon macro-settlement (>300ms silence or presence of response footer actions), reading the data-island text once into memory, resolving canonical ~formatId~, and caching the parsed AST via ~parserRegistry.settleContent(formatId, rawText)~ in the LRU store.
- The Preact root renders an improved header with complete functional parity:
  1. *Language Badge*: Format indicator (e.g. "Org Mode", "LaTeX", "Python").
  2. *View Toggle*: Instant flip between "Rendered View" and "Raw Source".
  3. *Block Folding*: Collapse/expand toggle for the code block body.
  4. *Primary Copy*: Direct clipboard copy from the ~:scope code-block code~ data-island.
  5. *Overflow Menu*: Secondary actions (copy as markdown, scoped subtree copy, wrap lines).

** 2. DuckDuckGo AI (Duck.ai) Platform Adapter

*** 2.1 DOM Architecture & Semantic Selectors
- Selectors are strictly bound to Duck.ai's semantic ~data-streamdown~ DOM hierarchy (~div[data-streamdown="code-block"]~, ~div[data-streamdown="code-block-body"]~, ~pre > code~).
- Absolute prohibition of dynamic React hash classes or unstable CSS module names.

*** 2.2 Pristine Code Extraction & MathML LaTeX Annotations
- Scraper extracts code directly from ~pre > code.textContent~ without regex stripping; line numbers generated via CSS pseudo-elements (~::before~) require zero string cleaning.
- High-fidelity math extraction parses raw LaTeX directly from MathML ~math > semantics > annotation[encoding="application/x-tex"]~ elements.

*** 2.3 Stream Settlement State Machine
- In-flight token streaming is detected via the presence of ~button[aria-label="Stop generating"]~.
- Stream finalization is detected via the presence of ~div[data-message-actions="true"]~ or the disappearance of the stop button combined with a 300ms debounce quiet period.

*** 2.4 Sibling Mount Anchor & Widescreen Layout
- Mounts adjacent sibling container inside an open Shadow Root; hides native block body with ~display: none~ to preserve the Data-Island.
- Host theme synchronization monitors ~document.documentElement[data-theme]~ and forwards changes to injected Shadow Roots.
- Layout controller injects ~--duckai-chat-max-width~ CSS custom property rules to provide widescreen presets without breaking host chat boundaries.

* Test Architecture & Verification Domain

** 1. Test Pyramid Tiers & Execution Scopes
- *Reference Standards*: Fully specified in [[file:docs/test-design.org][docs/test-design.org]] and verified in [[file:docs/audits/test-audit-report.org][docs/audits/test-audit-report.org]].
- *Unit Tests (~unit:~)* :: Fast (sub-millisecond to <10ms), hermetic, in-memory tests verifying pure logic, AST parsers, serializers, tokenizer rules, matchers, and isolated Preact components without disk compilation or host DOM overhead. Executed via ~deno task test:unit~.
- *Integration Tests (~integration:~)* :: Seam tests verifying multi-module collaboration across site adapters, DOM observers, Preact portal mounting, and reactive storage state, running against the standardized DOM fixture. Executed via ~deno task test:integration~.
- *End-to-End (E2E) Tests (~e2e:~)* :: High-fidelity verification validating full system behavior across two distinct modalities:
  1. *Software-Defined E2E*: Headless script-level tests validating bundled extension artifacts (~dist/dev/~), multi-adapter code-splitting, manifest declarations, and content script bootstrapping. Executed via ~deno task test:e2e~.
  2. *Prompt-Defined E2E*: Living specifications (~tests/ff-devtools_e2e-tests/*.org~) executed against real browsers via Firefox DevTools MCP using provider-specific, reusable evaluation scripts.
- *Selective Task Execution Policy* :: Developers and agents avoid running expensive full test suites during localized refactoring:
  - Run ~deno task test:unit~ when actively modifying pure logic, parsers, serializers, matchers, or data models.
  - Run ~deno task test:integration~ when modifying host adapters, DOM observers, or UI components.
  - Run ~deno task test:e2e~ or the complete ~deno task test~ pipeline ONLY when modifying ~build.ts~, ~manifest.json~, entrypoint bootstrapping, or when preparing milestone commits.

** 2. Test Discipline & Harness Standards
- *Single-Assertion AAA Discipline* :: Strict testing invariant where every automated test is structured as Arrange-Act-Assert verifying exactly one logical assertion, guaranteeing instant root-cause identification without masked cascading failures.
- *DOM Fixture Authority (~tests/fixtures/dom_fixture.ts~)* :: The single canonical source of truth for all test DOM polyfills (including ~:has()~ selector interception, style stubs, and storage resets). Individual test suites must never define bespoke DOM shims.
- *Component Testing Standard (~@testing-library/preact~)* :: Standardized Preact component test harness executing accessible queries (~getByRole~, ~getByText~) against clean DOM containers for unit tests, supplemented by targeted ~renderInShadow~ for explicit Shadow Root isolation verification.
- *Technical Debt Quarantine & Tracking Protocol* :: When test refactoring uncovers failures caused by known technical debt or architectural omissions in ~src/~, do NOT hastily mutate ~src/~. Mark the test as quarantined using ~ignore: true~ in ~Deno.test~ with a comment citing the ticket in ~.scratch/technical-debt/issues/<id>-<slug>.org~. Create the tracking ticket detailing context, assertion, and remediation milestone. Un-quarantining occurs strictly during the scheduled refactoring stage after verifying passing tests.
