#+TITLE: ADR 0001: Preact In-Situ Sibling Rendering
#+DATE: 2026-09-03

:PROPERTIES:
:STATUS: Accepted
:END:

* Status
Accepted

* Context
Gemini outputs Org-mode documents inside native Angular/Material code blocks (~.code-block~, ~<pre><code>~). We need a mechanism to present rich, interactive Org-mode AST views (collapsible headings, checkable boxes, tables, syntax highlighted code, drawers) without breaking Gemini's native DOM structure, message copying chrome, or streaming mutation observers.

We considered:
1. *Full DOM replacement*: Detaching the ~<pre>~ block entirely and replacing it with our root. (Risks crashing Gemini's Angular runtime and copy actions).
2. *Shadow DOM per block*: Attaching a shadow root to every code block. (Heavy stylesheet duplication across dozens of code blocks).
3. *In-situ sibling container*: Hiding the ~<pre><code>~ container and mounting an ~.orgmod-rendered-container~ as a sibling within the existing ~.code-block~ shell.

* Decision
We adopt *In-Situ Sibling Container Rendering* using Preact:
- Each detected Org code block retains its original ~<pre><code>~ element (hidden via CSS when rendered).
- A sibling ~<div class="orgmod-rendered-container">~ is mounted with Preact ~render(<OrgDocumentView />, container)~.
- Gemini's native copy button and container chrome remain untouched on the right.
- Injected action buttons (~[Org/Raw]~, ~[Fold/Expand]~) allow instant toggle between raw and rendered states.

* Consequences
** Positive
- Zero disruption to Gemini's Angular runtime, scroll mechanics, and native copy features.
- Seamless CSS variable sharing for dynamic dark/light theme adaptation without shadow root encapsulation overhead.
- Instant, flicker-free toggling between raw code and rendered Org views.

** Negative
- Global CSS classes must be strictly namespaced with ~.orgmod-*~ prefixes to avoid leaking into Gemini's host UI.
