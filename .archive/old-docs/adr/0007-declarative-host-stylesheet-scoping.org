#+TITLE: ADR 0007: Declarative Host Stylesheet Scoping via WebExtension Content Scripts
#+DATE: 2026-09-04

:PROPERTIES:
:STATUS: Accepted
:END:

* Status
Accepted

* Context
As the extension evolves from a Gemini-only tool toward supporting multiple conversational AI platforms (such as DuckDuckGo AI at ~duck.ai~), each platform introduces distinct DOM hierarchies, viewport geometries, and container classes.
Earlier architectural proposals considered a dynamic programmatic stylesheet loader in JavaScript that would inspect ~window.location.hostname~ and inject ~<link>~ or ~<style>~ elements at runtime. However:
1. *FOUC (Flash of Unstyled Content)*: Dynamic JS stylesheet injection occurs after page scripts initialize, causing visual jumping and layout thrashing.
2. *Security & CSP Overhead*: Dynamic ~<link>~ injection requires exposing stylesheets via ~web_accessible_resources~ in the extension manifest and navigating host page Content Security Policies.
3. *Cross-Platform Style Collisions*: Loading all platform stylesheets simultaneously in a single content script entry leads to selector collisions between platforms.

* Decision
We adopt *Declarative Host Stylesheet Scoping* directly within ~manifest.json~ using separate ~content_scripts~ entries:
1. *Universal Base Script*:
   The core content script (~content.js~), KaTeX distribution (~vendor/katex.min.*~), and platform-agnostic design system tokens (~styles/general.css~) are declared in the primary ~content_scripts~ entry matching all supported chat host domains (~gemini.google.com~, ~duck.ai~).
2. *Platform-Specific Stylesheet Entries*:
   Each chat platform's layout overrides and font-sizing rules are declared in dedicated ~content_scripts~ entries matching strictly that platform's URL pattern (e.g. ~styles/gemini.css~ matched solely to ~https://gemini.google.com/*~).
3. *Zero-FOUC Injection*:
   Both the base script and scoped stylesheets declare ~run_at: "document_start"~, allowing the browser engine to inject and apply platform layout rules synchronously before DOM rendering begins.

* Consequences
** Positive
- Zero runtime JavaScript overhead for stylesheet discovery or injection.
- Zero flash of unstyled content (FOUC); CSS is applied at ~document_start~ by the browser engine.
- Complete isolation: ~styles/gemini.css~ never executes or leaks into ~duck.ai~ or other future chat hosts.
- Eliminates the need for ~web_accessible_resources~ declarations for internal styles.

** Negative
- Adding support for a new chat host requires adding its URL pattern and corresponding CSS mapping to ~manifest.json~.
