#+TITLE: ADR 0003: Streaming Reconciliation and AST Caching
#+DATE: 2026-09-03

:PROPERTIES:
:STATUS: Accepted
:END:

* Status
Accepted

* Context
Gemini outputs tokens dynamically using chunked streaming. Parsing the AST on every micro-mutation during token generation causes severe CPU utilization, layout thrashing, and cursor instability. Furthermore, toggling between ~Org~ and ~Raw~ views within an active conversation should be instantaneous without reparsing.

* Decision
1. *Streaming Debounce & Settlement*: During active streaming mutations, AST re-parsing is throttled with a settlement window (~80ms-120ms debounce). The raw view remains active until streaming settles, after which the full Org AST is compiled and rendered.
2. *AST In-Memory Cache*: Parsed ASTs are cached per block element in a memory registry. Toggling ~View Raw~ / ~View Org~ reuses the cached AST instantly without re-parsing.
3. *Cache Eviction*: The AST cache is scoped to the active conversation and cleared when navigating away from the chat session or when the memory boundary is exceeded.

* Consequences
** Positive
- Smooth, non-blocking rendering during rapid AI token generation.
- Instantaneous switching between Org and Raw views.
- Clean memory lifecycle tied to conversation sessions.

** Negative
- Brief debounce delay before an actively streaming Org block settles into its rendered view.
