1. Executive Summary & Strategic Verdict

Preact is an ultra-lightweight (~3kB to 4.5kB minified + gzipped) virtual DOM library that provides the modern declarative component model of React with near-zero abstraction overhead over native Web standards. Originally conceived by Jason Miller in 2015, Preact has evolved into a premier frontend architecture for resource-constrained environments, high-performance dashboards, embedded widgets, and browser extensions operating within complex third-party Single Page Applications (SPAs) such as Google Gemini, ChatGPT, Claude, and GitHub.

Unlike React—which has transitioned toward complex scheduling fibers, asynchronous concurrent lanes, synthetic event delegation matrices, and server component pipelines resulting in a runtime footprint exceeding 45kB+ gzip—Preact adheres strictly to the philosophy of direct DOM alignment, native W3C event dispatching, and high-velocity reconciliation.

With the introduction of Preact Signals (~1.6kB core), Preact established a paradigm shift in web reactivity: fine-grained reactive state primitives that update real DOM nodes directly (bypassing the Virtual DOM reconciliation loop entirely for text nodes and dynamic attributes), achieving \(\mathcal{O}(1)\) DOM updates with 0ms component diffing overhead.

Strategic Verdict for Browser Extensions & Embedded UI: Preact, combined with `@preact/signals` and Shadow DOM encapsulation, is the optimal architectural standard for browser extensions and in-situ DOM injection. It provides:

  1. Negligible bundle footprint and sub-millisecond initial parse/execution time.
  2. Complete style and DOM isolation via native Shadow DOM.
  3. Surgical \(\mathcal{O}(1)\) UI updates without risking re-render churn or interfering with the host page's event loop.
  4. Clean lifecycle teardown via render(null, container), preventing memory leaks in dynamic, long-lived SPA sessions.

2. Architectural Comparison: Preact vs. React 18 / 19

Preact intentionally diverges from React in key architectural areas to minimize memory allocation, maximize execution speed, and stay close to browser primitives.

2.1. Reconciliation Call Stack Mechanics

React Fiber maintains a doubly-linked tree of fiber nodes representing work-in-progress and current states. This enables cooperative scheduling and interruptions, but incurs substantial heap allocations per node (~15-20 fields per Fiber).

Preact diffs Virtual DOM trees directly against existing DOM nodes or preceding VNodes. A Preact VNode is a lightweight JavaScript object: 

export interface VNode<P = {}> {
    type: ComponentType<P> | string;
    props: P & { children: ComponentChildren };
    key: any;
    ref: any;
    _dom: PreactNode | null;       // Reference to the rendered real DOM node
    _children: Array<VNode> | null; // Child VNodes
    _component: Component | null;  // Component instance (if class) or internal state container
    _depth: number;                // Nesting depth for diff prioritization
}

Because Preact holds a direct pointer _dom to the real DOM node, the diffing algorithm operates with minimal recursion depth and near-zero garbage collection pressure.

3. Core Syntax & Modern Standards

3.1. Modern JSX Transform (preact/jsx-runtime) vs Classic Pragma (h)

Modern Preact applications utilize the automatic JSX runtime introduced in modern ECMAScript standards (supported by TypeScript 4.1+, Deno, Vite, esbuild, and Rollup).

3.1.1. 1. Automatic JSX Runtime (Recommended Standard)

With automatic runtime configuration, developers do not need to manually import h or Fragment in every TSX/JSX file. 

{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "preact"
  }
}

Under this configuration:

  • <div class="card">Hello</div> transpiles to _jsx("div", { class: "card", children: "Hello" }).
  • <><span>A</span><span>B</span></> transpiles to _jsxs(Fragment, { children: [...] }).

3.1.2. 2. Classic Runtime (h Pragma)

When working in environments without automatic runtime transforms, configure the classic pragma explicitly: 

/** @jsx h */
/** @jsxFrag Fragment */
import { h, Fragment, render } from "preact";

const App = () => (
    <Fragment>
        <div class="header">Classic Runtime</div>
    </Fragment>
);

3.1.3. 3. HTM (Hyperscript Tagged Markup) - Zero-Build Environments

For browser extensions or runtime scripts requiring zero bundler/transpiler overhead, HTM provides JSX ergonomics via ES2015 tagged template literals: 

import { html, render } from "https://esm.sh/htm/preact";

const Button = ({ label, onClick }) => html`
    <button class="btn" onClick=${onClick}>
        <span>${label}</span>
    </button>
`;

render(html`<${Button} label="Click Me" onClick=${() => console.log("OK")} />`, document.body);

3.2. Attribute Normalization: class vs. className, for vs. htmlFor

Preact normalizes property names directly to the underlying DOM element properties or attributes:

  • class and className: Both are fully supported. In idiomatic Preact, standard class="foo bar" is preferred because it mirrors native HTML.
  • for and htmlFor: Both are fully supported for <label> elements.
  • Boolean Attributes: Passing true or "" (empty string) sets the boolean attribute/property (e.g. disabled, checked, readOnly, hidden, required). Passing false, null, or undefined removes the attribute and sets the DOM property to false.
// Idiomatic Preact: Clean, standard HTML attributes
export function LoginForm({ isSubmitting }: { isSubmitting: boolean }) {
    return (
        <form class="auth-form" method="dialog">
            <label for="user-email" class="form-label">Email Address</label>
            <input
                id="user-email"
                type="email"
                required
                disabled={isSubmitting}
                class="form-input"
            />
        </form>
    );
}

3.3. Style Property Handling & CSS Custom Properties

Preact provides flexible style property resolution:

  1. String Styles: Unlike React (which throws a runtime invariant error on string styles), Preact supports raw CSS strings: 

    <div style="display: flex; gap: 8px; align-items: center;" />

    Preact applies string styles directly via dom.style.cssText = style.

  2. Style Objects: CamelCase properties are supported as in React (backgroundColor, marginTop).

  3. CSS Custom Properties (Variables): CSS variables (keys starting with --) are natively handled by Preact via dom.style.setProperty(name, value): 

    <div style={{
    "--theme-accent": "#3b82f6",
    "--panel-opacity": 0.95,
    display: "flex",
    padding: 16 // Preact appends 'px' for non-unitless CSS properties
}}>
    Themed Panel
</div>
  4. Unitless Numbers: Preact maintains an internal table of unitless CSS properties (opacity, zIndex, flexGrow, lineHeight, order, etc.). For dimensional properties like width, height, and margin, numeric values automatically receive the px suffix.

4. Preact Hooks & State Architecture

Hooks in Preact are packaged in preact/hooks. They hook into Preact's internal options pipeline without adding weight to core components.

4.1. Core Hooks Reference

useReducer<S, A> [state, dispatch] = useReducer(reducer, init) Complex local state transitions with action dispatching.
useEffect useEffect(() => { ... return cleanup; }, deps) Asynchronous post-paint side-effects (runs after DOM commit).

4.2. The Preact-Exclusive useErrorBoundary Hook

React requires class components with componentDidCatch or getDerivedStateFromError to catch rendering exceptions. Preact introduces useErrorBoundary, enabling 100% functional error containment: 

import { useErrorBoundary } from "preact/hooks";
import type { ComponentChildren, JSX } from "preact";

interface SafeBoundaryProps {
    children: ComponentChildren;
    fallbackTitle?: string;
}

export function SafeBoundary({ children, fallbackTitle = "Component Error" }: SafeBoundaryProps): JSX.Element {
    const [error, resetError] = useErrorBoundary((err) => {
        console.error("[SafeBoundary Caught Exception]:", err);
    });

    if (error) {
        return (
            <div class="error-container p-4 bg-red-900/20 border border-red-500 rounded">
                <h4 class="text-red-400 font-semibold">{fallbackTitle}</h4>
                <p class="text-xs text-red-200 font-mono mt-1">{error.message}</p>
                <button
                    class="mt-2 px-3 py-1 bg-red-600 hover:bg-red-500 text-white text-xs rounded"
                    onClick={() => resetError()}
                >
                    Retry Component
                </button>
            </div>
        );
    }

    return <>{children}</>;
}

4.3. Ref Management: useRef, Callback Refs, and Forwarding

Preact supports three primary ref paradigms:

4.3.1. 1. Object Refs (useRef)

import { useRef, useEffect } from "preact/hooks";

export function AutoFocusInput() {
    const inputRef = useRef<HTMLInputElement>(null);

    useEffect(() => {
        inputRef.current?.focus();
    }, []);

    return <input ref={inputRef} class="search-field" placeholder="Search..." />;
}

4.3.2. 2. Callback Refs with Cleanup Pattern

Callback refs allow direct observation of when a DOM element is mounted or unmounted: 

import { useCallback, useRef } from "preact/hooks";

export function MeasuredElement() {
    const resizeObserverRef = useRef<ResizeObserver | null>(null);

    const measureCallback = useCallback((node: HTMLDivElement | null) => {
        if (node !== null) {
            // Element mounted
            resizeObserverRef.current = new ResizeObserver((entries) => {
                for (const entry of entries) {
                    console.log("Element dimensions:", entry.contentRect);
                }
            });
            resizeObserverRef.current.observe(node);
        } else {
            // Element unmounted
            resizeObserverRef.current?.disconnect();
            resizeObserverRef.current = null;
        }
    }, []);

    return <div ref={measureCallback} class="measured-box">Observed Content</div>;
}

4.3.3. 3. Ref Forwarding

In Preact, ref can be passed as a normal prop to function components, or wrapped with forwardRef from preact/compat for universal library interop: 

import type { JSX, Ref } from "preact";

interface CustomButtonProps extends JSX.HTMLAttributes<HTMLButtonElement> {
    innerRef?: Ref<HTMLButtonElement>;
    variant?: "primary" | "secondary";
}

export function CustomButton({ innerRef, variant = "primary", children, ...props }: CustomButtonProps) {
    return (
        <button ref={innerRef} class={`btn btn-${variant}`} {...props}>
            {children}
        </button>
    );
}

5. Preact Signals (@preact/signals) & Fine-Grained Reactivity

Preact Signals represent the most significant architectural evolution in modern frontend performance. Built upon `@preact/signals-core`, signals decouple state tracking from component render cycles.

5.1. Core Reactive Primitives

import { signal, computed, effect, batch, untracked } from "@preact/signals";

// 1. Reactive State Primitive
export const counter = signal<number>(0);

// 2. Memoized Derived Computation
export const isEven = computed<boolean>(() => counter.value % 2 === 0);

// 3. Side Effect with Automatic Dependency Tracking
const disposeEffect = effect(() => {
    console.log(`Current Count: ${counter.value}, IsEven: ${isEven.value}`);
});

// 4. Atomic Multi-State Mutation
export function resetAndIncrement(val: number) {
    batch(() => {
        counter.value = 0;
        counter.value += val;
    }); // Listeners and subscribers are notified exactly once!
}

5.2. The Direct DOM Bypass Superpower (\(\mathcal{O}(1)\) Updates)

The defining performance breakthrough of Preact Signals is the Direct DOM Bypass.

When a Signal is passed directly into JSX text content or standard HTML attributes: 

import { signal } from "@preact/signals";

const clickCount = signal(0);

// COMPONENT DOES NOT RE-RENDER WHEN clickCount CHANGES!
export function HighFrequencyCounter() {
    console.log("[HighFrequencyCounter Rendered]"); // Runs ONCE on mount

    return (
        <div class="counter-card">
            {/* Passing the Signal directly binds to the underlying Text DOM Node */}
            <h3>Clicks: {clickCount}</h3>
            <button onClick={() => clickCount.value++}>Increment</button>
        </div>
    );
}

5.2.1. Under the Hood: How Direct DOM Bypass Works

  1. During initial render, Preact encounters a Signal instance as a child node.
  2. Preact creates a native Text node in the DOM (document.createTextNode(String(signal.value))).

  3. Preact attaches a fine-grained subscriber directly to that Text node: 

    signal.subscribe(val => { textNode.data = val; });
  4. When clickCount.value++ is executed:
    • The HighFrequencyCounter function is NOT called.
    • No Virtual DOM trees are created or compared.
    • The browser directly mutates textNode.data in \(\mathcal{O}(1)\) time with 0ms reconciler overhead.

5.2.2. Comparison: Direct Signal vs. Signal Value Access

// Case A: Component Re-Renders (Accessed .value in render body)
function ComponentA() {
    return <span>{counter.value}</span>; // Subscribes ComponentA to counter updates
}

// Case B: Direct DOM Bypass (Zero Component Re-Renders)
function ComponentB() {
    return <span>{counter}</span>; // Subscribes Text Node directly to counter updates
}

5.3. Component-Scoped Signals: useSignal and useComputed

When state must be scoped to an individual component instance and cleaned up upon unmounting: 

import { useSignal, useComputed } from "@preact/signals";

export function SearchFilter({ items }: { items: string[] }) {
    const query = useSignal("");

    const filtered = useComputed(() => {
        const q = query.value.trim().toLowerCase();
        if (!q) return items;
        return items.filter(item => item.toLowerCase().includes(q));
    });

    return (
        <div class="search-container">
            <input
                value={query.value}
                onInput={(e) => (query.value = e.currentTarget.value)}
                placeholder="Filter items..."
            />
            <ul class="results-list">
                {filtered.value.map(item => (
                    <li key={item}>{item}</li>
                ))}
            </ul>
        </div>
    );
}

5.4. Module-Level Global Signals (Eliminating Context Providers)

Signals completely eliminate "Context Hell" and top-level provider re-render cascades in browser extensions and web apps: 

// src/store/extension-store.ts
import { signal } from "@preact/signals";

export interface ExtensionSettings {
    fullWidth: boolean;
    widthPercent: number;
    autoRenderOrg: boolean;
    hudCollapsed: boolean;
}

export const extensionSettings = signal<ExtensionSettings>({
    fullWidth: true,
    widthPercent: 94,
    autoRenderOrg: true,
    hudCollapsed: false,
});

export const toggleFullWidth = () => {
    extensionSettings.value = {
        ...extensionSettings.value,
        fullWidth: !extensionSettings.value.fullWidth,
    };
};

Any component across the entire codebase can import extensionSettings directly without wrapping the DOM tree in a <SettingsProvider>.

6. Browser Extension & DOM Injection Patterns

Browser extensions injecting UI into host web applications (e.g. Google Gemini, Claude, GitHub) face severe hostile-environment constraints:

  • Host CSS Bleed: Global stylesheets, CSS resets, or utility classes from the host page corrupt extension widgets.
  • Dynamic DOM Replacement: Host SPAs re-render entire message trees during AI streaming or client-side navigation.
  • Event Interception Traps: Host keyboard listeners intercept shortcut keystrokes before extension inputs receive them.

6.1. Pattern 1: Shadow DOM Encapsulation (Recommended for Floating HUD & Overlays)

Shadow DOM provides impenetrable boundary isolation for styles and DOM trees. 

import { render } from "preact";
import type { JSX } from "preact";
import { extensionSettings, toggleFullWidth } from "../store/extension-store.ts";

function FloatingHud(): JSX.Element {
    const s = extensionSettings.value;

    return (
        <div class={`hud-container ${s.hudCollapsed ? "collapsed" : "expanded"}`}>
            <header class="hud-header">
                <span class="hud-title">⚡ Gemini OrgUI</span>
                <button
                    class="hud-toggle"
                    onClick={() => {
                        extensionSettings.value = {
                            ...s,
                            hudCollapsed: !s.hudCollapsed,
                        };
                    }}
                >
                    {s.hudCollapsed ? "+" : "−"}
                </button>
            </header>
            {!s.hudCollapsed && (
                <div class="hud-body">
                    <button
                        class={`hud-btn ${s.fullWidth ? "active" : ""}`}
                        onClick={toggleFullWidth}
                    >
                        Width: {s.fullWidth ? `${s.widthPercent}%` : "Off"}
                    </button>
                </div>
            )}
        </div>
    );
}

export class ShadowHudMount {
    private hostEl: HTMLDivElement | null = null;
    private shadowRoot: ShadowRoot | null = null;

    mount(): void {
        if (typeof document === "undefined") return;
        if (document.getElementById("gemini-org-hud-host")) return;

        this.hostEl = document.createElement("div");
        this.hostEl.id = "gemini-org-hud-host";

        // Attach open Shadow Root
        this.shadowRoot = this.hostEl.attachShadow({ mode: "open" });

        // Inject Stylesheet
        const style = document.createElement("style");
        style.textContent = SHADOW_CSS;
        this.shadowRoot.appendChild(style);

        // Render Preact application directly into Shadow Root
        const container = document.createElement("div");
        this.shadowRoot.appendChild(container);
        render(<FloatingHud />, container);

        document.body.appendChild(this.hostEl);
    }

    unmount(): void {
        if (this.shadowRoot && this.hostEl) {
            const container = this.shadowRoot.querySelector("div");
            if (container) {
                render(null, container); // Preact lifecycle unmount
            }
            this.hostEl.remove();
            this.hostEl = null;
            this.shadowRoot = null;
        }
    }
}

6.2. Pattern 2: Contextual In-Situ Mounting (Embedding inside Host Message Blocks)

When mounting interactive toolbars directly above code blocks or inside AI chat turns, we utilize lightweight micro-mounts managed by a disconnected node tracker: 

import { render } from "preact";
import type { JSX } from "preact";

interface BlockActionProps {
    rawOrgText: string;
    onToggleFold: () => void;
}

function BlockActionToolbar({ rawOrgText, onToggleFold }: BlockActionProps): JSX.Element {
    const handleCopy = async (e: JSX.TargetedMouseEvent<HTMLButtonElement>) => {
        e.stopPropagation();
        await navigator.clipboard.writeText(rawOrgText);
    };

    return (
        <div class="org-block-toolbar" onClick={(e) => e.stopPropagation()}>
            <button class="toolbar-btn" onClick={onToggleFold}>Toggle Fold</button>
            <button class="toolbar-btn" onClick={handleCopy}>Copy Org Source</button>
        </div>
    );
}

export function mountBlockToolbar(targetContainer: HTMLElement, rawOrgText: string, onFold: () => void) {
    const mountPoint = document.createElement("div");
    mountPoint.className = "org-toolbar-mount";
    targetContainer.prepend(mountPoint);

    render(
        <BlockActionToolbar rawOrgText={rawOrgText} onToggleFold={onFold} />,
        mountPoint
    );

    return () => {
        render(null, mountPoint);
        mountPoint.remove();
    };
}

6.3. Keyboard Shortcut & Event Isolation in Injected Contexts

To prevent the host SPA (e.g. Gemini listening for hotkeys or Escape) from hijacking keypresses inside injected form fields: 

export function IsolatedSearchInput() {
    const handleKeyDown = (e: JSX.TargetedKeyboardEvent<HTMLInputElement>) => {
        // Stop propagation so host application keyboard listeners are not triggered
        e.stopPropagation();

        if (e.key === "Escape") {
            e.currentTarget.blur();
        }
    };

    return (
        <input
            type="text"
            class="search-box"
            onKeyDown={handleKeyDown}
            onKeyUp={(e) => e.stopPropagation()}
            onKeyPress={(e) => e.stopPropagation()}
            placeholder="Type query..."
        />
    );
}

7. Memory Management & Lifecycle Cleanup

Memory management is paramount in browser extensions. If a host SPA runs continuously for days across thousands of message turns, uncleaned Preact roots will retain closures, DOM nodes, and signal listeners, causing massive heap bloat.

7.1. The Proper Preact Unmounting Protocol

In Preact, tearing down a virtual tree is executed by rendering null into the container: 

import { render } from "preact";

// Mounting
const container = document.getElementById("my-root")!;
render(<MyComponent />, container);

// Clean Unmounting: Triggers all unmount hooks, effect cleanups, and clears references
render(null, container);

7.1.1. What Happens Internally During render(null, container):

  1. Preact traverses the active VNode tree stored on container._children.
  2. Invokes all componentWillUnmount lifecycle methods in reverse topological order.
  3. Executes all cleanup functions returned by useEffect, useLayoutEffect, and useSignalEffect.
  4. Removes event listener proxies attached to DOM elements.
  5. Detaches child DOM nodes from the container.
  6. Nulls out internal references (container._children = null), releasing VNode graphs for Garbage Collection.

7.2. MutationObserver Automatic Cleanup Manager

To prevent zombie mounts when the host SPA removes parent DOM nodes without notifying the extension: 

import { render } from "preact";
import type { JSX } from "preact";

export class DOMInjectionLifecycleManager {
    private activeMounts = new Map<HTMLElement, () => void>();
    private observer: MutationObserver | null = null;

    constructor() {
        this.initObserver();
    }

    private initObserver(): void {
        this.observer = new MutationObserver((mutations) => {
            for (const mutation of mutations) {
                for (const removedNode of Array.from(mutation.removedNodes)) {
                    if (removedNode instanceof HTMLElement) {
                        this.sweepDisconnectedRoots(removedNode);
                    }
                }
            }
        });

        this.observer.observe(document.body, {
            childList: true,
            subtree: true,
        });
    }

    mount(container: HTMLElement, vnode: JSX.Element): () => void {
        render(vnode, container);

        const unmountFn = () => {
            render(null, container);
            this.activeMounts.delete(container);
        };

        this.activeMounts.set(container, unmountFn);
        return unmountFn;
    }

    private sweepDisconnectedRoots(detachedSubtree: HTMLElement): void {
        for (const [container, unmountFn] of this.activeMounts.entries()) {
            if (detachedSubtree.contains(container) || !document.body.contains(container)) {
                console.debug("[LifecycleManager] Sweeping detached Preact root:", container);
                unmountFn();
            }
        }
    }

    destroy(): void {
        this.observer?.disconnect();
        for (const unmountFn of this.activeMounts.values()) {
            unmountFn();
        }
        this.activeMounts.clear();
    }
}

9. Pitfalls, Gotchas & Anti-Patterns

9.1. 1. Controlled Input Cursor Jumps

9.1.1. The Problem:

In React, controlled inputs (value={val} with onChange) synchronously hijack keystrokes to maintain selection and cursor coordinates. In Preact, because state updates are debounced and batched via microtasks, updating state asynchronously during typing can cause the text cursor to jump to the end of the input field.

9.1.2. The Solution:

  • Use onInput instead of onChange for real-time text binding.
  • For high-velocity inputs, bind directly to a Signal or use uncontrolled inputs with defaultValue and refs:
// ANTI-PATTERN: Can cause cursor jumping under microtask delay
function BadInput() {
    const [val, setVal] = useState("");
    return <input value={val} onChange={(e) => setVal(e.currentTarget.value)} />;
}

// BEST PRACTICE A: Using Signal Direct Binding (Synchronous & No Cursor Jump)
function GoodSignalInput() {
    const text = useSignal("");
    return (
        <input
            value={text.value}
            onInput={(e) => (text.value = e.currentTarget.value)}
        />
    );
}

// BEST PRACTICE B: Uncontrolled Input with Ref for Complex Masking
function GoodUncontrolledInput({ onCommit }: { onCommit: (val: string) => void }) {
    const inputRef = useRef<HTMLInputElement>(null);

    return (
        <input
            ref={inputRef}
            defaultValue=""
            onBlur={() => onCommit(inputRef.current?.value || "")}
        />
    );
}

9.2. 2. The props.children Array Assumption Trap

9.2.1. The Problem:

In React, React.Children.map is used to handle single, multiple, or undefined children. In Preact, to save memory, props.children is:

  • undefined if no children exist.
  • An object/VNode if 1 child exists.
  • An array of VNodes if 2+ children exist.

Calling props.children.map(...) directly will crash at runtime when only 1 child is provided!

9.2.2. The Solution:

Always use toChildArray from preact: 

import { toChildArray } from "preact";
import type { ComponentChildren } from "preact";

export function ListWrapper({ children }: { children: ComponentChildren }) {
    // Safely normalizes children into a flat Array<VNode | string | number>
    const childArray = toChildArray(children);

    return (
        <ul class="item-list">
            {childArray.map((child, idx) => (
                <li key={idx} class="item-entry">{child}</li>
            ))}
        </ul>
    );
}

9.3. 3. Shallow Equality Breakdown in memo

9.3.1. The Problem:

Passing anonymous arrow functions or inline object literals to memoized components breaks shallow equality checks: 

// ANTI-PATTERN: Re-creates object and function references every render
<MemoizedChild
    style={{ color: "red" }}
    onClick={() => doAction(id)}
/>

9.3.2. The Solution:

Use useCallback, useMemo, or pass persistent Signal instances: 

// BEST PRACTICE: Stable references
const handleClick = useCallback(() => doAction(id), [id]);
const cardStyle = useMemo(() => ({ color: "red" }), []);

return <MemoizedChild style={cardStyle} onClick={handleClick} />;

10.1. The Preact options Middleware Pipeline

10.1.1. Practical Gem: Custom Frame-Aligned Rendering Scheduler

You can sync Preact rendering directly to requestAnimationFrame for ultra-smooth 60fps animations: 

import { options } from "preact";

// Align all asynchronous state updates to the browser's refresh rate
let renderQueue: Array<() => void> = [];

options.debounceRendering = (renderCallback) => {
    if (renderQueue.push(renderCallback) === 1) {
        requestAnimationFrame(() => {
            const queue = renderQueue;
            renderQueue = [];
            queue.forEach((cb) => cb());
        });
    }
};

11.1. Before: Imperative Vanilla DOM (hud.ts)

11.2. After: Declarative Preact + Signals (hud.tsx)

import { render } from "preact";
import type { JSX } from "preact";
import { signal, computed } from "@preact/signals";

// 1. Reactive Extension State
export interface HudState {
    collapsed: boolean;
    fullWidth: boolean;
    widthPercent: number;
    autoRenderOrg: boolean;
}

export const hudState = signal<HudState>({
    collapsed: false,
    fullWidth: true,
    widthPercent: 94,
    autoRenderOrg: true,
});

export const PRESET_WIDTHS = [80, 90, 94, 100] as const;

// 2. Declarative Preact Component
interface HudViewProps {
    onRenderAll: () => void;
    onFoldAll: () => void;
}

export function HudView({ onRenderAll, onFoldAll }: HudViewProps): JSX.Element {
    const s = hudState.value;

    const toggleCollapse = () => {
        hudState.value = { ...s, collapsed: !s.collapsed };
    };

    const toggleWidth = () => {
        hudState.value = { ...s, fullWidth: !s.fullWidth };
    };

    const setPreset = (val: number) => {
        hudState.value = { ...s, widthPercent: val, fullWidth: true };
    };

    const toggleAutoOrg = () => {
        hudState.value = { ...s, autoRenderOrg: !s.autoRenderOrg };
    };

    return (
        <div class={`orgmod-hud ${s.collapsed ? "minimized" : ""}`} data-gemini-org="hud">
            {/* Header */}
            <div class="orgmod-hud-header" onClick={toggleCollapse} data-gemini-org="hud-header">
                <span class="orgmod-hud-title" data-gemini-org="hud-title">⚡ OrgUI</span>
                <span class="orgmod-hud-collapse-icon" data-gemini-org="hud-collapse-btn">
                    {s.collapsed ? "+" : "−"}
                </span>
            </div>

            {/* Body */}
            {!s.collapsed && (
                <div class="orgmod-hud-body" data-gemini-org="hud-body">
                    {/* Row 1: Width Controls */}
                    <div class="orgmod-hud-row">
                        <button
                            class={`orgmod-hud-btn ${s.fullWidth ? "active" : ""}`}
                            onClick={toggleWidth}
                            title="Toggle Full-Screen Width (Alt+W)"
                            data-gemini-org="hud-width"
                        >
                            Width: {s.fullWidth ? `${s.widthPercent}%` : "Off"}
                        </button>
                        <div class="orgmod-hud-presets" data-gemini-org="hud-presets">
                            {PRESET_WIDTHS.map((val) => (
                                <button
                                    key={val}
                                    class={`orgmod-hud-preset ${s.fullWidth && s.widthPercent === val ? "active" : ""}`}
                                    onClick={() => setPreset(val)}
                                    data-gemini-org="hud-preset"
                                >
                                    {val}%
                                </button>
                            ))}
                        </div>
                    </div>

                    {/* Row 2: Org Controls */}
                    <div class="orgmod-hud-row">
                        <button
                            class={`orgmod-hud-btn ${s.autoRenderOrg ? "active" : ""}`}
                            onClick={toggleAutoOrg}
                            title="Auto-render Org Mode Blocks"
                            data-gemini-org="hud-auto"
                        >
                            Auto-Org: {s.autoRenderOrg ? "ON" : "OFF"}
                        </button>
                        <button
                            class="orgmod-hud-btn"
                            onClick={onRenderAll}
                            title="Toggle Render All Blocks (Alt+O)"
                            data-gemini-org="hud-renderall"
                        >
                            Render All
                        </button>
                        <button
                            class="orgmod-hud-btn"
                            onClick={onFoldAll}
                            title="Toggle Fold/Expand All Blocks (Alt+F)"
                            data-gemini-org="hud-foldall"
                        >
                            Fold All
                        </button>
                    </div>
                </div>
            )}
        </div>
    );
}

// 3. Mount Controller
export class PreactHudController {
    private mountNode: HTMLElement | null = null;
    private onRenderAll: () => void;
    private onFoldAll: () => void;

    constructor(onRenderAll: () => void, onFoldAll: () => void) {
        this.onRenderAll = onRenderAll;
        this.onFoldAll = onFoldAll;
    }

    mount(): void {
        if (typeof document === "undefined") return;
        if (document.getElementById("orgmod-hud-root")) return;

        this.mountNode = document.createElement("div");
        this.mountNode.id = "orgmod-hud-root";
        document.body.appendChild(this.mountNode);

        render(
            <HudView
                onRenderAll={this.onRenderAll}
                onFoldAll={this.onFoldAll}
            />,
            this.mountNode
        );
    }

    unmount(): void {
        if (this.mountNode) {
            render(null, this.mountNode);
            this.mountNode.remove();
            this.mountNode = null;
        }
    }
}
