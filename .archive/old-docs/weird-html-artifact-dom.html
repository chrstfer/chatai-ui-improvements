#+TITLE: Technical Audit: Preact 11 API Accuracy, Idioms, and Best Practices #+DATE: [2026-09-06 Sun 00:46]

  • Executive Summary

The provided document (~preact-syntax-best-practices.txt~) is substantially a Preact 10.x document presented under a modern heading. While the architectural analysis regarding Signals, Shadow DOM mounting, and event handling is high quality, the document contains several direct factual errors and outdated conventions when evaluated specifically against Preact 11.

Preact 11 introduces intentional breaking changes to shed legacy baggage, align closer with modern web standards, and restructure its TypeScript types.

  • Core Preact 11 Discrepancies & Direct API Inaccuracies

1. Automatic ~px~ Suffixing Removed from Core

  • Document Claim: Under Section 3.3 ("Style Property Handling"), the document states: #+BEGIN_SRC tsx padding: 16 // Preact appends 'px' for non-unitless CSS properties #+END_SRC And asserts: /"For dimensional properties like width, height, and margin, numeric values automatically receive the px suffix."/

  • Preact 11 Reality: False in Preact 11 Core. In Preact 11, automatic ~px~ suffixing for numeric CSS properties was removed from Preact Core to save bundle size and avoid property lookup tables. It is now exclusively available through the compatibility layer (~preact/compat~). In pure Preact 11 core, ~style={{ padding: "16px" }}~ is required.

2. Ref Passing and ~forwardRef~ Redundancy

  • Document Claim: Section 4.3 ("Ref Management") suggests wrapping function components with ~forwardRef~ from ~preact/compat~ for ref handling.

  • Preact 11 Reality: In Preact 11, refs are forwarded by default. Standard function components accept ~ref~ directly as a regular prop (e.g., ~({ ref, children }: { ref?: Ref })~). The ~forwardRef~ wrapper is deprecated/unnecessary unless strictly maintaining legacy React 18 library compat.

3. TypeScript ~JSX~ Namespace Reorganization

  • Document Claim: Section 7.1 ("Essential Preact TypeScript Types") and 7.3 list types under the ~JSX.*~ namespace:

    • ~JSX.TargetedEvent<Target, Event>~

    • ~JSX.HTMLAttributes~

    • ~JSX.CSSProperties~

  • Preact 11 Reality: In Preact 11, the global JSX namespace was trimmed to strictly what TypeScript's compiler requires (JSX.Element, JSX.IntrinsicElements, etc.) to resolve long-standing TS type pollution and auto-import collisions. Most utility types are moved directly to the root preact namespace (e.g., TargetedEvent, HTMLAttributes, CSSProperties directly imported from "preact").

4. useRef Initial Value Contract

  • Document Claim: Shows ~useRef(null)~ and ~useRef<ResizeObserver null |>(null)~, but types it generally without noting signature enforcement.

  • Preact 11 Reality: Aligning with TypeScript 5+ and React 19 standards, Preact 11 changes ~useRef~ to strictly require an initial argument (i.e. useRef() without arguments is no longer a valid overload; it must be useRef<T>(null) or useRef<T>(initialValue) to resolve RefObject<T> variance).

5. VNode Internal Architecture (_dom vs VNode Structure)

  • Document Claim: Quotes the internal ~VNode~ interface containing _dom as a direct reference to the rendered real DOM node.

  • Preact 11 Reality: Following the January 2026 security fixes and Preact 11 architecture, VNodes enforce strict constructor instance checks to prevent arbitrary object/JSON injection. While _dom remains an internal pointer, relying on or documenting private underscored properties (_dom, _children, _depth) is discouraged as Preact 11 refactored parts of the hydration and diffing internal queues (such as Hydration 2.0 multi-node root returns and createPortal moving into core).

  • Required Corrections for a Preact 11 Target

  1. Remove reliance on automatic ~px~ injection: Explicitly format numeric pixel properties as strings (e.g., padding: "16px" or height: "100px") unless explicitly configuring preact/compat.

  2. Eliminate forwardRef mentions: Update all custom components to consume ref directly as standard props without preact/compat wrappers.

  3. Import types from "preact" directly: Replace JSX.TargetedEvent, JSX.HTMLAttributes, and JSX.CSSProperties with TargetedEvent, HTMLAttributes, and CSSProperties from "preact".

  4. Note Object.is Hook Equality: Mention that Preact 11 switches hook dependency comparisons (useEffect, useMemo, useCallback) from loose equality to Object.is, correctly handling NaN and -0/+0 without manual guards.

  5. Acknowledge createPortal in Core: Preact 11 moves portal support directly into core (preact), making portal mounts easier without pulling in compat packages.
