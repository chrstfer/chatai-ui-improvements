* Executive Summary & Purpose
Before launching the expansive multi-platform and GFM capabilities of Phase 3, a focused pre-phase milestone is executed to harden existing core features and deliver the **v0.2.0 production release**.

This plan consolidates all architectural and interaction decisions settled through rigorous multi-round grilling. It delivers a clean browser action toolbar toggle with a non-destructive synchronous teardown barrier, confines the Floating HUD to the chat column with bilateral edge snapping and inward expansion, establishes a standardized ~HostLayoutController~ seam, and scales user requests symmetrically with model responses across the widened conversation column.

* Architectural Decisions & Specifications

** 1. Browser Action Toolbar Toggle & Clean Teardown State Machine (Issue 01)
- *Manifest V3 Integration*:
  - Register ~"action": { "default_title": "AI Chat UI Improvements" }~ in ~src/manifest.json~.
  - Register background script under ~"background": { "scripts": ["src/entrypoints/background.ts"] }~.
  - Update ~build.ts~ to compile ~src/entrypoints/background.ts~ into ~dist/dev/src/entrypoints/background.js~ (and release).
- *Per-Tab Activation Memory*:
  - Background script manages ~tabStates: Map<number, boolean>~ in memory.
  - State persists across page reloads (~F5~ / ~Ctrl+R~) until the specific tab is closed.
  - When deactivated on a tab, background sets ~browser.action.setBadgeText({ tabId, text: "OFF" })~ with a muted gray badge color.
  - When active, the badge text is cleared.
- *Synchronous Cancellation & Teardown Barrier*:
  - Clicking the toolbar action dispatches a toggle message to the active tab's content script.
  - On deactivation, ~adapter.destroy()~ executes an immediate synchronous cancellation barrier:
    1. Sets an internal ~this.destroyed = true~ latch on the adapter and injector.
    2. Disconnects host ~MutationObserver~ instances immediately.
    3. Clears all active ~setTimeout~ and ~requestAnimationFrame~ macro-settle debounce handles.
    4. Unmounts all turn Preact roots and restores native ~<code-block>~ elements (~display: none~ removed) via ~injector.destroyAll()~.
    5. Unmounts the Floating HUD from the DOM via ~unmountHud()~.
    6. Destroys host-specific layout overrides via ~adapter.layoutController.destroy()~.
    7. Retains in-memory caches (~AstCache~ and ~ViewStateCache~) so that subsequent re-enabling re-hydrates instantly (0ms) without reparsing.
  - Zero broken markup, orphaned containers, or hidden host elements remain in the DOM.

** 2. Floating HUD: Chat-Column Contained Overlay & Bilateral Snapping (Issue 02)
- *Layer Separation & Flow Independence*:
  - The Floating HUD is rendered on a dedicated overlay layer (~position: fixed~, ~z-index: 999999~).
  - It overlays chat messages without altering document flow or layout underneath.
- *Chat Column Containment*:
  - Boundary clamping and snapping are strictly contained within the active chat column rather than the outer window boundaries.
  - ~SiteAdapter~ provides ~getChatColumnBounds(): { left: number; right: number; top: number; bottom: number } | null~:
    - On Gemini: queries ~.conversation-container~ (falling back to viewport margins on zero-state home screen).
    - On Duck.ai: queries the conversation column (stable selector finalized in Phase 3 Stage 1).
  - When dragging, ~x~ is clamped within ~[column.left + 16, column.right - hudWidth - 16]~.
- *Bilateral Snapping (~1em / 16px)*:
  - Pointer movement is 1:1 continuous during dragging without magnetic resistance.
  - On pointer release (~pointerup~), if the HUD is within 32px of a column boundary, it smoothly snaps to 16px (~1em) from that boundary:
    - *Right-Anchored*: Snaps to ~column.right - hudWidth - 16px~; expands horizontally to the *left* (towards the center).
    - *Left-Anchored*: Snaps to ~column.left + 16px~; expands horizontally to the *right* (towards the center).
- *Default Spawn Position*:
  - On fresh sessions with no stored position, spawns docked at the **bottom-right** of the chat column:
    - Horizontally: docked ~1em (16px) inside the right column boundary.
    - Vertically: docked **2em (~32px) above the bottom prompt input container**.
    - Mode: started in **compact collapsed pill mode**.

** 3. Symmetrical Widescreen & Multi-Host Layout Controller (Issue 03)
- *Standardized ~HostLayoutController~ Seam*:
  - Defined in ~src/core/contracts/layout.ts~:
#+BEGIN_SRC typescript
export interface HostLayoutController {
    initialize(targetDoc?: DocumentLike): void;
    apply(settings: ExtensionSettings, targetDoc?: DocumentLike): void;
    destroy(targetDoc?: DocumentLike): void;
}
#+END_SRC
  - ~SiteAdapter~ exposes ~readonly layoutController?: HostLayoutController~.
  - ~build.ts~ compiles ~src/chat/<host>/styles/layout.css~ into ~layout.generated.ts~ across supported host directories.
- *Gemini Widescreen Scaling & 708px Ceiling Override*:
  - Widens the centered conversational column (~.conversation-container~) to ~var(--ext-chat-max-width, 94%)~ with ~margin-inline: auto~.
  - Overrides Gemini's scoped 708px ceiling on inner model markdown elements:
#+BEGIN_SRC css
body.ext-fullwidth-active {
    & .enable-extended-and-xl-grid .md-content > :not(#_),
    & .enable-extended-and-xl-grid .conversation-container .md-content > :not(#_),
    & .md-content > :not(#_),
    & .model-response-text,
    & message-content,
    & .response-container-content,
    & .response-content {
        max-width: 100% !important;
        box-sizing: border-box !important;
    }
}
#+END_SRC
  - Expands ~user-query~ to 100% of the conversational column.
- *Stable 90% Max-Width Cap (Read & Edit Parity)*:
  - Long user query bubbles (~.user-query-bubble-with-background~) and prompt edit boxes (~.user-query-container:has(textarea), .edit-mode~) are capped at **90%** of the column width.
  - Leaving a 10% indentation on the left visually preserves speech bubble identity.
  - Both read mode and edit mode share identical 90% max-width bounds, guaranteeing **zero layout jump** when clicking the edit pencil.
  - Short prompts remain compact, right-anchored bubbles with intact copy and edit buttons.
- *Duck.ai Isolation & Compatibility*:
  - Duck.ai natively controls its chat container and input form width via ~--duckai-chat-max-width~.
  - ~DuckLayoutController~ manages ~--duckai-chat-max-width~ without requiring custom CSS overrides.
  - Gemini CSS remains strictly isolated to Gemini tabs.

** 4. Cleanup: Ad-Hoc Hotkey Deprecation
- Remove existing ad-hoc ~Alt + W~ and ~Alt + O~ keydown listeners from ~src/entrypoints/content.ts~.
- Prevents keystroke interception or shortcut collisions in the v0.2.0 release. Formal user-configurable keybindings are deferred to future settings architecture.
