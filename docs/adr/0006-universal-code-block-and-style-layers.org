#+TITLE: ADR 0006: Universal In-Situ Code Block Shell, 3-Layer Style Mapping, and Fingerprinted AST Caching
#+DATE: 2026-09-04

:PROPERTIES:
:STATUS: Accepted
:END:

* Status
Accepted

* Context
As the extension expanded to provide rich rendering, HUD overlays, outline folding, dynamic toolbars, and layout scaling, several structural challenges emerged:
1. *Imperative DOM Manipulation*: Code block management and HUD injection previously relied on imperative DOM operations (~document.createElement~, manual ~.style.display~ toggling, disjoint ~render()~ calls), violating declarative Preact principles and increasing fragility during streaming updates.
2. *Non-Org Code Block Folding*: Code blocks in programming languages (e.g. Python, Rust, JavaScript, JSON) lacked folding capabilities, causing long code snippets to consume excessive vertical conversational space.
3. *Style Mapping Coupled to Synthetic DOM*: Testing layout styles required synthetic DOM environments (~deno-dom~, ~jsdom~) which exhibit edge-case divergence with CSS custom properties and computed styles.
4. *Virtual Scroll Unmount Thrashing*: Chat interfaces aggressively unmount past conversation turns when scrolling. Re-parsing complex documents upon scroll remounting caused UI micro-stutters.

* Decision
We adopt a declarative Preact-first architecture across all UI and DOM touchpoints:

** 1. Universal In-Situ Code Block Shell (~StructuredMessageContainer~ & ~InSituCodeBlock~)
All code blocks (both Org-mode and standard programming languages) are wrapped by a universal in-situ Preact shell:
- *Single Preact Root*: Each host code block receives exactly one Preact mount container. Sub-elements (such as toolbars) are projected into host headers using Preact portals (~createPortal~).
- *Universal Folding*: For non-Org blocks (and raw Org view), folding collapses the raw ~<pre>~ element and displays a compact line-count summary badge (~📦 [lang] (N lines) — Click to expand~).
- *Renderer Delegation*: Org blocks delegate rendering to ~OrgDocumentView~, exposing document outline folding and interactive drawers.

** 2. Three-Layer Style Architecture
We decouple layout styling into three distinct, single-responsibility layers:
1. *Layer 1 (Pure Domain Core)*: Deterministic mapping function ~computeLayoutStyles(settings: ExtensionSettings)~ returning ~{ cssVars: Record<string, string>, classNames: string[] }~ with zero DOM dependencies. Fully testable in headless Deno.
2. *Layer 2 (I/O & DOM Adapter)*: Minimal bridge ~applyLayoutDeclarations(target: HTMLElement, declarations)~ setting CSS variables and toggling classes on ~document.documentElement~ / ~document.body~.
3. *Layer 3 (Preact Integration)*: Reactive hook ~useLayoutSync(settings)~ invoking Layer 2 inside ~useEffect~ whenever settings mutate.

** 3. Persistent Content Fingerprint AST Cache
To prevent re-parsing latency during virtual scrolling:
- Code blocks are fingerprinted using a fast $O(1)$ locally obvious hashing strategy (~fnv1a(text[0..128] + len + lang)~).
- Parsed ASTs and fold states are retained in ~BlockStore~ keyed by fingerprint.
- When dynamic unmounting occurs, ~DomObserver~ signals node removal, pruning DOM references while preserving the AST cache. Re-mounted blocks hydrate instantly.

** 4. Unified Extension Root & Dev-Only Gating
- All global extension UI (HUD, Version Overlay, Layout Synchronization) is mounted under a single root component (~ExtensionRoot~) wrapped in ~SettingsProvider~ and ~BlockStoreProvider~.
- DevTools inspection APIs (~__GeminiOrgMod~, ~gemini-org-inspect~) and ~VersionOverlay~ are strictly compiled behind ~if (__DEV__)~, allowing esbuild to eliminate them completely from release builds.

* Consequences
** Positive
- 100% declarative Preact component tree; eliminated all imperative DOM creation and style mutations.
- Unified folding and toolbar interface for all code blocks across the conversation.
- Pure headless unit testing for layout styles without DOM mocks.
- Zero-lag virtual scroll hydration powered by persistent content fingerprint caching.
- Clean separation between release bundles and development debug tools.

** Negative
- Small component abstraction overhead, easily absorbed by modern browser JavaScript runtimes.
