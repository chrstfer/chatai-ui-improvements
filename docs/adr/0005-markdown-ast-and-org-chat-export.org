#+TITLE: ADR 0005: Markdown AST Pipeline and Org-Mode Chat Export
#+DATE: 2026-09-04

:PROPERTIES:
:STATUS: Accepted
:END:

* Status
Accepted

* Context
Users need to export full Gemini conversations into native, authentic Org-mode (~.org~) documents. Gemini presents conversational turns rendered as CommonMark/GFM markdown with interspersed code blocks, including code blocks containing Org-mode documents.

We considered two architectural approaches:
1. *Strategy A: Direct DOM Walker*: Recursively crawling rendered HTML nodes (~<h1>~-~<h6>~, ~<p>~, ~<ul>~, ~<code-block>~) and serializing on the fly.
   - /Trade-off/: Highly coupled to Gemini's volatile Angular/Polymer DOM structure, brittle against UI button clutter, difficult to isolate in automated unit tests.
2. *Strategy B: Markdown AST Pipeline*: Extracting clean message text streams into an isolated, strongly-typed CommonMark/GFM AST (~src/languages/markdown/~), transforming the AST into Org plaintext (~src/languages/org/export/~), and unwrapping embedded Org code blocks with dynamic heading re-leveling.
   - /Trade-off/: Requires implementing a robust markdown parser, but yields 100% pure TypeScript logic, zero DOM coupling, and complete unit testability.

* Decision
We adopt *Strategy B: Markdown AST Pipeline* with the following specifications:
1. *Submodule Organization*:
   - Move Org rendering into ~src/languages/org/~.
   - Create a dedicated CommonMark/GFM parser and AST in ~src/languages/markdown/~.
   - Implement the export engine in ~src/languages/org/export/~.
2. *Contextual Heading Re-Leveling*:
   - User and Assistant turns establish base level-1 headings (~* User~, ~* Gemini~).
   - Internal Markdown headings at level $h$ map to level $1 + h$ (~*~ $\times (1 + h)$).
   - Embedded Org-mode code blocks are unwrapped (markdown fences dropped) and their headings are re-leveled to $d_{\text{current}} + k - 1$ where $d_{\text{current}}$ is the active section depth.
3. *Turn Metadata Drawers*:
   - Each turn heading contains an Org property drawer with ~:ROLE:~, ~:MESSAGE_INDEX:~, ~:TURN_INDEX:~, and ~:TIMESTAMP:~.
4. *Host-Agnostic Stylesheet Decoupling*:
   - Split stylesheets into ~src/styles/general.css~ (host-agnostic design tokens, Org rendering, base HUD geometry) and ~src/styles/gemini.css~ (Gemini-specific DOM overrides and response font size scoping).

* Consequences
** Positive
- Zero coupling to Gemini DOM churn for export formatting.
- 100% unit-testable markdown parsing and Org serialization.
- Pure host-agnostic styling in ~general.css~ enabling future reuse across other chat interfaces (e.g. Claude, ChatGPT).
- High fidelity Org-mode exports with preserved subtree hierarchies and structured metadata drawers.

** Negative
- Additional parser maintenance in ~src/languages/markdown/~.
