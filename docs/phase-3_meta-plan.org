* 1. Phase 3 Overview & Execution Flow

Phase 3 transitions the extension from a single-platform in-situ Org-mode viewer (Gemini, v0.2.0) into a robust, multi-platform conversational workbench. It introduces native DuckDuckGo AI (=duck.ai=) support, autonomous Single Page Application (SPA) navigation resilience, a tripartite feature hierarchy (=features/ast/=, =features/renderers/=, =features/serializers/=), an abstract serialization engine with dependency injection, a JSON AST Intermediate Representation (IR), and tree-structured conversation backup with multi-path selection and local file saving.

Every stage in Phase 3 is executed under a strict protocol: developing an individual stage implementation plan, reviewing existing codebase usage and seams, and stress-testing decisions via =/grill-with-docs= prior to code modification.

* 2. Architectural Principles & Tripartite Organization

** 2.1 Role-First Tripartite Architecture
To avoid empty stubs for asymmetric formats (e.g. diagrams that only need a renderer, or data dumps that only need a serializer), feature implementations are split into three dedicated directories:

** 2.2 Strict Directional Dependencies
- =contracts/= depends on nothing outside itself.
- =features/ast/= depends only on =contracts/=. Zero Preact, zero DOM, zero CSS.
- =features/serializers/= depends on =features/ast/= and =contracts/=. Zero Preact, zero DOM.
- =features/renderers/= depends on =features/ast/=, =contracts/=, and Preact.
- =chat/= (host adapters) depends on =contracts/= and provides injection targets for renderers.

** 2.3 JSON AST as Intermediate Representation (IR)
The JSON AST under =src/features/ast/json/= serves a dual role:
1. An authentic AST for rendering arbitrary JSON code blocks via =features/renderers/json/=.
2. A canonical Intermediate Representation (IR) for conversational turns and markup conversions, enabling an O(M + N) conversion pipeline rather than point-to-point transpilers.

** 2.4 Dependency Injection via Lazy Factories
Registries (=ChatAdapterRegistry=, =RendererRegistry=, =SerializerRegistry=) use the factory-provider Dependency Injection pattern:
- The registry maintains a map of string keys to factory functions: =() => Promise<T> | T=.
- The production composition root (=src/index.ts=) registers dynamic import factories, preserving Deno 2 code-splitting chunks (=dist/dev/duckai-*.js=).
- Headless unit tests inject synchronous mock instances directly, eliminating dynamic import or bundler complexity.

** 2.3 Duck.ai Implementation Details
- *DOM Selectors & Types* (=src/chat/duckai/selectors.ts=, =types.ts=): Strictly bound to semantic =data-streamdown= hierarchy (=div[data-streamdown="code-block"]=, =div[data-streamdown="code-block-body"]=, =pre > code=). Absolute prohibition of generated React hash classes.
- *Pristine Code Extraction* (=src/chat/duckai/scraper.ts=): Extract code from =pre > code.textContent= without regex stripping (CSS pseudo-element line numbers require zero cleaning). Extract clean LaTeX from MathML =annotation[encoding="application/x-tex"]=.
- *Mutation & Settlement Observer* (=src/chat/duckai/domObserver.ts=): Monitor =button[aria-label="Stop generating"]= (in-flight) and finalization via =div[data-message-actions="true"]= with a 300ms macro-settle debounce window.
- *Non-Destructive Sibling Injector* (=src/chat/duckai/injector.tsx=): Mount adjacent sibling container inside an open Shadow Root; hide native block body with =display: none= maintaining the Data-Island pattern.
- *Host Theme & Layout* (=src/chat/duckai/theme.ts=, =layout.ts=): Synchronize with =document.documentElement[data-theme]= and manage =--duckai-chat-max-width= layout overrides.

** 2.4 SPA In-Session Chat Switch Observer Resilience
- =SiteAdapter.initialize()= hooks window =popstate= and wraps =history.pushState= / =history.replaceState=.
- Differentiates in-chat prompt submissions from true thread switches by comparing thread ID URL pathnames and root container DOM identity.
- On thread switch: synchronously destroys mounted Preact roots and disconnected observers for the old chat, flushes active turn contexts, and binds observers to the newly mounted stream container.

* 5. Stage 3: Two-Phase Math & Tripartite AST Foundation

** 3.1 Objective
Shield LaTeX mathematical expressions from prose entity expansion and establish pure, headless AST engines for CommonMark/GFM and JSON IR.

** 3.2 Two-Phase LaTeX Math Tokenization
- *Files*: =src/features/ast/org/inlineParser.ts=
- *Phase 1 (Delimiting & Shielding)*: Delimit inline ($...$, \(...\)) and display ($$...$$, \begin{equation}...\end{equation}) math fragments into immutable AST tokens /first/.
- *Phase 2 (Selective Entity Expansion)*: Perform Greek entity expansion strictly on non-math prose text runs. Untouched LaTeX ASCII syntax is delivered directly to KaTeX for native typesetting.

** 3.3 CommonMark + GFM Pure AST Engine
- *Files*: =src/features/ast/markdown/=
- Implement headless block and inline parsers assembling a pure AST hierarchy:
  - Document root and ATX headings (H1-H6) with hierarchical section nesting.
  - GitHub Alert callouts (=[!NOTE]=, =[!TIP]=, =[!IMPORTANT]=, =[!WARNING]=, =[!CAUTION]=).
  - Pipe tables with alignment colons, task lists (=- [ ]= / =- [x]=), and code fences.

** 3.4 JSON AST Intermediate Representation (IR)
- *Files*: =src/features/ast/json/=
- Build pure JSON AST parser assembling a deterministic node tree representing objects, arrays, and primitives.
- Provides standard conversion primitives allowing conversational turns to be represented as structured JSON data.

** 3.5 Completion Criteria
- [ ] Math expressions render cleanly in KaTeX without character corruption from premature Greek entity expansion.
- [ ] CommonMark and GFM AST parsers produce deterministic ASTs with 100% headless test coverage.
- [ ] JSON AST parser accurately parses arbitrary JSON payloads.

* 6. Stage 4: Headless Serializers & Comprehensive Test Suite

** 4.1 Objective
Construct the headless serialization engine implementing =ConversationSerializer= for Org-mode, Markdown, and JSON, validated by an exhaustive edge-case test suite.

** 4.2 Serializer Implementations
- *OrgSerializer* (=src/features/serializers/org/orgSerializer.ts=):
  - Emits top-level frontmatter (#+TITLE:, #+DATE:, #+OPTIONS:).
  - Emits turn headlines (* User: <prompt>, ** Assistant) with property drawers (:PROPERTIES: :TURN_ID: ... :END:).
  - Wraps code blocks in column 0 #+BEGIN_SRC <lang> and math in \begin{equation}.
- *MarkdownSerializer* (=src/features/serializers/markdown/markdownSerializer.ts=):
  - Emits H1 title or frontmatter, User prompt blockquotes, and assistant prose.
  - Implements dynamic code fence sizing: detects inner backtick sequences and wraps outer fences in N + 1 backticks (````) or tildes (~~~).
- *JsonSerializer* (=src/features/serializers/json/jsonSerializer.ts=):
  - Serializes conversation turns into a structured JSON document holding complete turn metadata, segments, and timestamps.
- *SerializerHandler* (=src/features/serializers/handler.ts=):
  - Centralized dispatcher coordinating serializer selection and delegating linear turn sequences.

** 4.3 Comprehensive Serializer Test Suite
- *Files*: =tests/serializers/serializer_test.ts=
- Exhaustive verification across extreme syntax fixtures:
  - Nested code blocks containing raw backticks and tildes.
  - Multiline LaTeX math equations with sub/superscripts.
  - Pipe tables with escaped pipe characters and unicode content.
  - Multi-turn conversation sequences.

** 4.4 Completion Criteria
- [ ] =OrgSerializer=, =MarkdownSerializer=, and =JsonSerializer= satisfy =ConversationSerializer=.

* 7. Stage 5: Chat History Persistence, HUD Tree Flyout & File Export

/Reference: [[file:../.scratch/conversation-history/spec.org][.scratch/conversation-history/spec.org]], Issues 01 & 02/

** 5.1 Objective
Provide persistent, tree-structured conversation backup in =browser.storage.local=, an interactive tree visualizer in the Floating HUD with multi-branch selection, and direct client-side file saving.

** 5.2 Subsystem Architecture
1. *Tree Storage Engine* (=src/features/history/conversationStore.ts=):
   - Appends completed turns upon macro-settlement.
   - Computes deterministic node hashes (=FNV-1a(parentTurnId + userQuery + turnIndex)=) to fork branches upon prompt edits or regenerations.
   - Zero-permission LRU eviction: Automatically purges oldest conversations when usage exceeds 8MB, remaining safely within the default 10MB quota without requiring =unlimitedStorage=.
2. *Interactive HUD Tree Flyout* (=src/views/history/ConversationTreeFlyout.tsx=):
   - Rendered inside Floating HUD Shadow Root as a smooth leftward drawer.
   - Interactive hierarchical tree diagram visualizing turn nodes with prompt summaries.
   - Path selection logic: Selecting a leaf node automatically computes and highlights the continuous root-to-leaf branch path; supports selecting multiple divergent branch paths concurrently.
   - Resolves selected paths into an ordered linear array =readonly ConversationTurnNode[]=.
   - Action bar: "Select All", "Select Active Branch", "Clear Selection", Format Toggle (=.org= vs =.md= vs =.json=).
3. *Direct Client-Side File Saving* (=src/features/export/fileSave.ts=):
   - Creates browser blob URI (=URL.createObjectURL(new Blob([content], { type: serializer.outputMimetype }))=) and triggers download.
   - Clean auto-generated filenames based on configurable pattern (default: =<chat-slug>-<YYYYMMDD-HHMMSS>.<ext>=).
   - Fallback "Copy to Clipboard" action with checkmark confirmation.

** 5.3 Completion Criteria
- [ ] All completed turns persist to =browser.storage.local= upon settlement.
- [ ] Prompt edits and response regenerations fork distinct branches in storage.
- [ ] HUD flyout visualizes branch tree and computes valid multi-path linear arrays.
- [ ] Direct blob download exports complete multi-turn documents in =.org=, =.md=, or =.json=.
