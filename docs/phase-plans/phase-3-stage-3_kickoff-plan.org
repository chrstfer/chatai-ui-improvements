* 1. Mission & Architectural Scope

In accordance with [[file:phase-3_meta-plan.org][docs/phase-3_meta-plan.org]] (§5), [[file:audits/20260914_test-audit/phase-3-stage-3_test-plan.org][docs/audits/20260914_test-audit/phase-3-stage-3_test-plan.org]], and the Five-Pillar Feature Hierarchy ([[file:../CONTEXT.org][CONTEXT.org]] §3), Stage 3 establishes the pure headless Abstract Syntax Tree (AST) foundation under =src/features/parsers/=, with zero presentation, DOM, or browser coupling:

1. *Two-Phase Math Tokenization*: Shield inline (~$...$~, ~\(...\)~) and display (~$$...$$~, ~\[...\]~, ~\begin{equation}...\end{equation}~) LaTeX mathematical notation from premature prose Greek entity expansion, delivering pristine ASCII syntax directly to KaTeX via a shared headless math parser (=src/features/parsers/math/=).
2. *CommonMark + GFM Headless AST Engine*: Pure block and inline parsers (=src/features/parsers/markdown/=) assembling document roots, ATX headings with hierarchical section nesting, GitHub Alert callouts, pipe tables with column alignment, task lists, and code fences.
3. *Canonical JSON AST & IR Engine*: Strongly-typed JSON AST parser (=src/features/parsers/json/=) and bidirectional ~AstIrTranslator~ converting between conversational turns and tree-structured ~JsonTurnIr~ (with ~parentId~ and ~parentResponseIndex~ for ordered tree branches).
4. *Parser Registry & Code-Splitting*: Lazy dynamic-import registration in ~ParserRegistry~ (~"org"~, ~"markdown"~, ~"json"~) with content-hash settlement caching.
