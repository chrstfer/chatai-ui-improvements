* 1. Overview & Architectural Objectives

** Scope & Purpose
In accordance with =docs/phase-3_meta-plan.org= (§7), Stage 5 delivers the conversation persistence, interactive branching visualizer, and client-side export subsystem:
1. *Conversation Tree Store & Hash-Forking*: Stores multi-turn conversations in =browser.storage.local= with deterministic node hashing (=FNV-1a(parentTurnId + userQuery + turnIndex)=) to fork branches upon prompt edits or regenerations.
2. *Zero-Permission 8MB LRU Eviction Engine*: Automatically purges the oldest stored conversations when total storage usage exceeds 8MB, operating strictly within the default 10MB WebExtension storage quota without requesting elevated permissions (=unlimitedStorage=).
3. *Interactive HUD Tree Flyout Component*: Preact component rendered inside the Floating HUD Shadow Root displaying conversation branches, leaf-to-root path resolution, and multi-branch selection.
4. *Direct Client-Side File Saving*: Generates browser blob URLs for instant download (.org, .md, .json) with clean autogenerated filenames and clipboard fallback.

This document establishes the test architecture, storage isolation invariants, component test matrices, and verification gates for Stage 5.

* 4. Subsystem Verification Matrices

** 4.1 Tree Storage & Branch-Forking Matrix (=src/features/history/conversationStore.ts=)

#+BEGIN_SRC text
Turn 0 (Root) ───► Turn 1 ───► Turn 2 (Original)
                      │
                      └───► Turn 2' (Regenerated / Edited Branch)
#+END_SRC

| Condition / Operation | Action | Expected Storage State | Invariant Assertion |
|---+---+---+---|
| *Initial Turn* | Append User prompt + Assistant reply | New conversation created with single turn node | Root node has ~parentTurnId: null~ |
| *Sequential Turn* | Append follow-up turn | Child node appended to current leaf | ~parentTurnId~ matches preceding turn ID |
| *Prompt Edit / Regeneration* | Submit new prompt against existing turn | Forked branch node created with unique hash ID | Original branch remains intact; tree contains 2 leaves |
| *Thread Switching* | Change active chat URL | Active conversation pointer updates | Prior conversation thread persisted in storage |

** 4.2 Zero-Permission 8MB LRU Eviction Matrix (=src/features/history/lruEviction.ts=)

| Total Storage Usage | Number of Stored Threads | Action / Event | Expected Eviction Behavior |
|---+---+---|---|
| *< 8MB* (e.g. 4.2MB) | 12 threads | Turn appended | Zero evictions; storage persists normally |
| *>= 8MB* (e.g. 8.4MB) | 25 threads | Settlement completed | Oldest conversation thread by ~lastAccessedAt~ is evicted |
| *Active Thread Protection* | Active thread is oldest | Quota exceeded | Eviction skips active thread and purges second-oldest |
| *Multi-Thread Pruning* | Large payload (9.5MB) | Settlement completed | Multiple oldest threads purged in LRU order until < 8MB |

** 4.3 Branch-Path Resolution Matrix (=src/features/history/branchResolution.ts=)

| Tree Topology | Selection Target | Resolved Output Sequence |
|---+---+---|
| Linear 3-turn thread | Leaf Turn 2 | ~[Turn 0, Turn 1, Turn 2]~ |
| 2-branch fork at Turn 1 | Forked Leaf Turn 2' | ~[Turn 0, Turn 1, Turn 2']~ |
| Multi-path selection | Leaf Turn 2 and Turn 2' | Disjoint linear sequences or merged tree export |

** 4.4 Interactive HUD Tree Flyout Component Matrix (=src/views/history/ConversationTreeFlyout.tsx=)

Tests utilize =@testing-library/preact= and accessible queries:
- *Mounting*: Verifies flyout mounts inside Shadow Root with role ~dialog~ and label ~Conversation History~.
- *Node Rendering*: Verifies prompt snippets render with correct turn index labels.
- *Selection Interactions*:
  - Clicking a node triggers ~onSelectTurn(turnId)~.
  - Clicking "Select Active Branch" selects all nodes along active trajectory.
  - Clicking "Clear" resets selection state.
- *Format Toggle*: Verifies format radio group toggles between ~org~, ~markdown~, and ~json~.
- *Export Button*: Verifies clicking "Export" invokes serialization and file save callback with linear turn array.

* 5. Storage Hermeticity & Test Isolation Invariant

Storage tests must strictly maintain isolation to prevent flaky test cross-talk:
1. *Reset Before and After*: Every storage test must invoke =resetTestStorage()= in a =finally= block.
2. *Quota Mocking*: Provide synthetic byte-size overrides to verify the 8MB threshold without allocating 8MB of physical heap data in every test run.
3. *Component Teardown*: Preact flyout tests must call =cleanup()= and =domCleanup()=.
